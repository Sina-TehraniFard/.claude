# /c-cmd-gen

Claude Codeカスタムコマンド（`c-` プレフィックス必須）を対話的に生成・更新する。ファイルを保存するまで完了ではない。

## 行動原則

- 推測しない。要件・設計・変更内容は各フェーズの節目でユーザーに確認してから次に進む
- 各確認は1回で明確に行う。同じ確認を言い方を変えて繰り返さない
- 専門用語は平易な言葉で説明する
- 依頼されていない機能を追加しない。シンプルさを優先する

## フェーズ1: 意図判定

ユーザー入力が既存コマンドの更新（言及・修正・追加要求）か、新規作成（未言及、新規要求）かを判定する。この判定は誤ると後続フェーズ全体が無駄になるため、判定結果（更新/新規）を最初の確認提示で必ず明示し、誤りがあれば訂正を受け付ける。

**更新の場合**：Globで `~/.claude/commands/c-*.md` と `.claude/commands/c-*.md` を検索し対象を読み込む。見つからなければ検索パターンや候補をユーザーに提示し、対象を確定させる。「作り直して」のように変更内容が特定できない曖昧な指示の場合は、現在の構造を要約した上で「どこをどう変えたいか」を掘り下げて聞く（新規作成側と同様、曖昧なまま先に進まない）。変更内容が明確な場合は、現在の構造の要約と要求内容をあわせて1回で確認を取る。

**新規作成の場合**：引数が空 or `interactive` なら AskUserQuestion で「何をするコマンドか」「入力は何か（ファイル/テキスト/引数なし）」を聞く。引数があれば内容を理解した上で要約確認する。

続けて以下を確認する（不明点のみでよい。自明なら聞かない）：
- 具体的な使用場面・入出力の例
- 個人利用かチーム共有か
- モデルによる自動起動を許すか、`/c-xxx` 明示呼び出し専用か
  - 自動起動: `description` に発話トリガー例を含め、類似コマンド/スキルと差別化する
  - 明示専用: frontmatterに `disable-model-invocation: true` を追加する

要件が固まったら要約を1回提示し、合意を得てからフェーズ2へ進む。

## フェーズ2: 設計と生成

要件から以下を設計し、提案として1回提示する（コマンド名と命名理由、allowed-tools選定理由、処理フローの概要、想定される出力形）。

**allowed-tools選定の目安**：コード分析→Read/Grep/Glob/Task、ファイル操作→Read/Write/Edit、コマンド実行→Bash/Read、対話重視→AskUserQuestion+関連ツール。タスクの実態に応じて過不足なく選ぶ。

合意が得られたら、以下の構造でコマンド本文を生成する。Globで見つかった既存の `c-*.md` の中から、生成対象と性質が近いもの（対話重視か/ツール構成が近いか）を1つ実際に読んで見出し構成・文体を揃える（存在しないファイルを参照先として想定しない）。

```
---
description: "..."
argument-hint: "..."
allowed-tools: "..."
---

# /c-コマンド名
[目的1-2文]

## 行動原則
[このコマンドが守るべき制約・トーン]

## Step 1〜N: [処理フロー]
[各ステップの具体的な指示。冗長な確認テンプレートの反復は避け、必要な箇所のみ確認を挟む]

## エラーハンドリング（対象が存在する場合）
[想定される失敗ケースと対応。例: 対象ファイル不在、入力が要件を満たさない]
```

生成物を全文提示し、フィードバックを反映して調整する。満足が得られるまで繰り返す。

## フェーズ3: 保存

保存先（個人用 `~/.claude/commands/` / プロジェクト共有 `.claude/commands/` / その他）とファイル名（`c-` + 動詞始まり + 小文字ハイフン + 15字以内が目安）を確認し、Write/Editで保存する。

保存後、保存先パスと使い方の例を報告して完了とする。
