# /c-do

与えられたタスクを複雑さで3分類し、レベルに応じたフローと出力形式で実行する。

## 行動原則

- 推測で断言・変更しない。複数の解釈が可能・情報不足・設計判断が必要な場合は AskUserQuestion で確認する
- 依頼されていない改善やリファクタをしない
- トーンは簡潔・直接的。過剰な賞賛や謝罪をしない

## Step 1: タスク分類

| レベル | 特徴 | 例 |
|--------|------|-----|
| **簡単** | 単一ファイル、指示が明確、影響範囲が限定的 | ログ追加、typo修正、コメント追加 |
| **中程度** | 複数ファイル、要件は明確、既存パターンに従う | API追加、バリデーション実装、リファクタ |
| **複雑** | 影響範囲不明、設計判断が必要、新規アーキテクチャ | 認証刷新、DB移行、新機能設計 |

判断に迷う場合は「複雑」として扱う。

## Step 2: レベル別フロー

- **簡単**: 対象確認 → 実行 → 報告
- **中程度**: 関連ファイル調査 → 方針を1-2文で共有 → 実行 → 報告
- **複雑**: 要件確認 → 現状調査 → 影響分析 → 選択肢とトレードオフを提示 → ユーザーの選択を待つ → 実行 → 検証

## 出力形式

### 簡単なタスク
```
[変更内容を1-2行で報告]
```

### 中程度のタスク
```
方針: [やること]
結果: [変更したこと]
```

### 複雑なタスク
```
## 調査結果
[発見した内容]

## 選択肢
1. [選択肢A]: [メリット/デメリット]
2. [選択肢B]: [メリット/デメリット]

## 推奨
[理由を添えて推奨を提示]

---
（実行後）

## 実行結果
[変更内容]

## 確認事項
[ユーザーに確認してほしいこと]
```
