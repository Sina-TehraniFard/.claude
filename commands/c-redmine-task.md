# /c-redmine-task

worklog の Redmine に、依頼された作業をチケットとして起票する。作業ディレクトリに関係なく、ユーザー設定に登録済みの MCP `redmine` を使う。

## 行動原則

- 案件（プロジェクト）が依頼から決まらないときだけ聞く。質問はチャットの本文に書く
- 依頼に無い項目（説明・担当者・優先度・並び順）は入れない
- ID は覚えた値を使わず、毎回ツールで引く。案件やトラッカーは増減する

## Step 1: 案件を決める

`list_projects` で案件の一覧を引き、依頼の言葉（ava、askul、np、自分の活動 など）と識別子・名前を突き合わせる。個人開発・ブログ・勉強は「自分の活動」（識別子 self）。どれにも当たらない、または複数に当たるときは候補を並べて聞く。

## Step 2: 中身を決める

- チケット名: 依頼の言葉のまま短く書く。`[案件名]` を頭に付けない（ボードの列で案件が分かる）。機能や施策の単位で複数作るときは `【機能名】作業名` の形にする
- 「〇〇と同じ内容で」と言われたら、`search_issues` か `read_issues` で元のチケットを探し、作業名の並びをそのまま写して `【】` の中だけを替える。元が見つからなければ探した言葉を添えて聞く
- 期間: 言われなければ開始日・期日とも今日（日本時間）。「来週」などは絶対日付に直す
- トラッカーは「タスク」、ステータスは既定の「新規」。ID は `capable_issue_properties`（project_id を指定）で引く

## Step 3: 確かめてから作る

1. `create_new_issue` を `validate_only: true` で呼び、全件が通ることを確かめる
2. 通ったら同じ値で `create_new_issue` を呼ぶ
3. 作ったチケットを表で報告する（番号・チケット名・期間）。リンクは `https://worklog.scriptlab.jp/issues/<番号>`

## エラーハンドリング

- MCP の `redmine` が無い、または繋がらない: `claude mcp list` で状態を確かめる。AWS の認証切れ（`Token has expired` など）なら、`! aws sso login --sso-session scriptlab` を打つよう1行で伝えて止める
- 検証でエラー: エラー文をそのまま示し、直す値が依頼から決まらなければ聞く。決まらないまま作らない
- 作成の途中で失敗: 作れた分の番号と、作れなかった分を分けて報告する
