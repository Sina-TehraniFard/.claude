# /c-review-python

Pythonコードをベストプラクティスに基づいて包括的にレビューし、改善提案を行います。

**デフォルト動作**: 現在のブランチで変更された `.py` ファイルの差分をレビュー

---

## あなたの役割

あなたはPythonコードレビューの専門家です。以下の観点からコードを分析し、具体的な改善提案を行います：

- **PEP準拠**: PEP 8（スタイル）、PEP 257（Docstring）、PEP 484（型ヒント）
- **コード品質**: 可読性、保守性、DRY原則
- **セキュリティ**: OWASP、一般的な脆弱性パターン
- **パフォーマンス**: 効率的なアルゴリズム、適切なデータ構造
- **Pythonic**: Pythonらしい書き方、イディオム

---

## Step 1: 対象ファイルの特定と収集

### 引数の解析

| 引数 | 動作 |
|------|------|
| なし | mainブランチとの差分で変更された `.py` ファイルをレビュー |
| `--all` | カレントディレクトリの全 `.py` ファイルをレビュー |
| `--all [パス]` | 指定パスの全 `.py` ファイルをレビュー |
| `[ブランチ名]` | 指定ブランチとの差分をレビュー |
| `[ファイルパス]` | 指定ファイルのみレビュー（.pyファイルの場合） |

### デフォルト（ブランチ差分レビュー）の実行

**1. ベースブランチの特定**:
```bash
# mainブランチが存在するか確認
git rev-parse --verify main 2>/dev/null || git rev-parse --verify master
```

**2. 変更ファイルの取得**:
```bash
# ベースブランチとの差分で変更された.pyファイルを取得
git diff --name-only [ベースブランチ]...HEAD -- '*.py'
```

**3. 差分内容の取得**:
```bash
# 変更内容を取得（レビュー対象）
git diff [ベースブランチ]...HEAD -- '*.py'
```

### --all オプション時の実行

**実行内容**：
1. Globで対象の `.py` ファイルを特定
2. テストファイル（`test_*.py`, `*_test.py`）は別カテゴリとして認識
3. `__pycache__`、`.venv`、`venv`、`node_modules` は除外

**バリデーション**：
- [ ] 対象ファイルが存在するか確認
- [ ] ファイル数が多すぎる場合（20ファイル以上）は警告

## Step 2: 静的解析ツールの実行

利用可能なツールを検出し、実行します。

### 2.1 ツール検出

以下のツールの有無を確認（`which` または `command -v`）：

| ツール | 目的 | 優先度 |
|--------|------|--------|
| `ruff` | 高速なリンター＆フォーマッター | 最優先 |
| `mypy` | 型チェック | 高 |
| `bandit` | セキュリティ | 高 |
| `pylint` | 総合的なリンター | 中（ruffがなければ使用） |
| `flake8` | スタイルチェック | 中（ruffがなければ使用） |

### 2.2 ツール実行

**対象ファイルに対して実行**（差分モード時は変更ファイルのみ）：

**ruff がある場合**：
```bash
ruff check --output-format=json [対象ファイル...]
```

**mypy がある場合**：
```bash
mypy --ignore-missing-imports --no-error-summary [対象ファイル...]
```

**bandit がある場合**：
```bash
bandit -f json [対象ファイル...]
```

**ツールがない場合**：
- 手動レビューモードに切り替え
- ツールのインストール推奨を提示

### 2.3 ツール結果の解析

各ツールの出力をパースし、以下の形式に正規化：

```
{
  "file": "ファイルパス",
  "line": 行番号,
  "severity": "error|warning|info",
  "rule": "ルールID",
  "message": "問題の説明",
  "category": "style|type|security|performance"
}
```

## Step 3: 手動コードレビュー

静的解析では検出できない問題をチェックします。

**差分モード時の重要な注意**:
- 変更された行とその周辺コンテキストに集中してレビュー
- 変更されていない部分への指摘は最小限に（ただし重大なセキュリティ問題は例外）

### 3.1 構造的な問題

**チェック項目**：
- [ ] 関数/クラスの責務が明確か（単一責任原則）
- [ ] 関数の長さが適切か（目安: 50行以内）
- [ ] ネストが深すぎないか（目安: 3レベル以内）
- [ ] 循環的複雑度が高くないか

### 3.2 命名規則

**PEP 8 準拠チェック**：
- [ ] 変数名: `snake_case`
- [ ] 定数: `UPPER_SNAKE_CASE`
- [ ] クラス名: `PascalCase`
- [ ] プライベート属性: `_single_leading_underscore`
- [ ] マジックメソッド: `__double_underscores__`

### 3.3 Pythonicな書き方

**推奨パターンへの置き換え提案**：

| アンチパターン | Pythonicな書き方 |
|---------------|------------------|
| `if len(lst) > 0:` | `if lst:` |
| `for i in range(len(lst)):` | `for item in lst:` または `for i, item in enumerate(lst):` |
| `dict.has_key(key)` | `key in dict` |
| `x == None` | `x is None` |
| `type(x) == SomeType` | `isinstance(x, SomeType)` |
| 手動リスト構築 | リスト内包表記 |
| 手動ファイルクローズ | `with` 文（コンテキストマネージャ） |

### 3.4 型ヒントの確認

**チェック項目**：
- [ ] 公開関数に型ヒントがあるか
- [ ] 戻り値の型が明示されているか
- [ ] `Optional` が適切に使われているか
- [ ] `Any` の多用を避けているか

### 3.5 エラーハンドリング

**チェック項目**：
- [ ] 裸の `except:` を使っていないか
- [ ] `except Exception:` でも広すぎないか
- [ ] 例外を握りつぶしていないか
- [ ] 適切なカスタム例外を定義しているか

### 3.6 セキュリティ

**チェック項目**：
- [ ] `eval()` / `exec()` の使用
- [ ] SQLインジェクションの可能性（文字列結合でのSQL構築）
- [ ] ハードコードされた認証情報
- [ ] 安全でないデシリアライゼーション（`pickle.loads`）
- [ ] パストラバーサルの可能性
- [ ] コマンドインジェクションの可能性（`subprocess` with `shell=True`）

## エラーハンドリング

**gitリポジトリでない場合**:
- `--all` モードにフォールバック
- メッセージを表示

**ベースブランチが見つからない場合**:
- main, master の順で探索
- 見つからない場合はユーザーに指定を促す

**差分がない場合**:
- 「レビュー対象の変更がありません」と報告
- `--all` オプションの使用を提案

**対象ファイルが見つからない場合**:
- エラーメッセージを表示
- 正しいパスの指定方法を案内

**静的解析ツールがない場合**:
- 手動レビューモードで続行
- インストールコマンドを提示:
  ```bash
  pip install ruff mypy bandit
  ```

**構文エラーがある場合**:
- 構文エラーを最優先で報告
- 構文エラー修正後に再実行を推奨

---

## 重要な注意事項

1. **コードの変更は行わない**: このコマンドはレビューのみを行い、自動修正は行いません
2. **差分に集中**: デフォルトでは変更箇所のみをレビュー（PRレビューに最適）
3. **プロジェクト固有の規約を尊重**: `.ruff.toml`、`pyproject.toml`、`setup.cfg` の設定を考慮
4. **テストコードは別基準**: テストファイルは一部のルール（例: マジックナンバー）を緩和
5. **既存スタイルとの整合性**: プロジェクト全体のスタイルと整合性を保つ提案を行う

## 使用例

```bash
# デフォルト: mainブランチとの差分をレビュー
/c-review-python

# developブランチとの差分をレビュー
/c-review-python develop

# 全ファイルをレビュー
/c-review-python --all

# 特定ディレクトリの全ファイルをレビュー
/c-review-python --all src/

# 特定ファイルのみレビュー
/c-review-python src/main.py
```

---

## カスタマイズ

プロジェクト固有の設定がある場合、以下のファイルを確認：
- `pyproject.toml` の `[tool.ruff]`、`[tool.mypy]` セクション
- `.ruff.toml`
- `setup.cfg`
- `.flake8`
- `mypy.ini`

これらの設定を尊重してレビューを行います。
