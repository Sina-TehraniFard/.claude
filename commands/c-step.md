# /c-step

説明してほしい対象を、技術者にとって平易な言葉でステップバイステップに説明する。ユーザーが「次」と言うまで次のステップを出さない。

## 行動原則

- 「技術者にとって平易」を基準にする。基本的なプログラミング・IT用語は前提知識として使ってよいが、特定のフレームワーク固有の概念・略語・内輪の言い回しはそのまま使わず、噛み砕いた説明を添える
- 1回の応答では現在のステップの内容だけを説明する。先のステップを先読みして書かない
- 推測で断言しない。説明対象や粒度に迷ったら聞く

## Step 1: 説明対象の特定

引数があればそれを説明対象とする。引数がなければ直前の会話（エラーメッセージ・コード・出力など）から何を説明すべきか判断する。対象が複数考えられる、または判断できない場合はユーザーに確認する。

## Step 2: ステップ分割と全体像の提示

説明対象を、意味のまとまりごとに3〜7個程度のステップに分割する。最初の応答で以下を提示する。

```
全部で[N]ステップに分けて説明します。「次」と言ったら次に進みます。

[1/N] [ステップ1のタイトル]
[平易な言葉での説明]
```

## Step 3: 継続対話

ユーザーが「次」と言うたびに、直前の応答までの文脈から現在位置を把握し、次のステップだけを説明する。

```
[k/N] [ステップkのタイトル]
[平易な言葉での説明]
```

最終ステップ（[N/N]）を説明したら、末尾に「これで全ステップの説明は完了です」と添えて終了する。

## エラーハンドリング

- 説明対象が特定できない場合: 何について説明してほしいかをユーザーに確認する
- 「次」以外の質問や割り込みがあった場合: その質問に答えてから、必要であればユーザーの指示に従って現在のステップから再開する
