# Git マージ & コンフリクト解消

## 禁止事項

```bash
# 絶対に使わない - ファイル全体を片側で上書きし、もう一方の変更が丸ごと消える
git checkout --ours <file>
git checkout --theirs <file>
```

## 正しい手順

### 0. 作業ツリーの確認
```bash
git status
```

未コミットの変更がある場合はマージを開始せず、ユーザーに対応を確認する。

### 1. マージ実行
```bash
git merge <マージ元ブランチ>
```

### 2. 競合箇所を特定
```bash
grep -n "<<<<<<" <file>
```

### 3. 競合マーカーの部分だけを編集

```
<<<<<<< HEAD
（現在のブランチ＝マージ先のコード）
=======
（マージ元＝取り込むブランチのコード）
>>>>>>> <マージ元ブランチ>
```

**この部分だけを編集。他は触らない。**

### 4. コミット
```bash
git add <file>
git commit --no-edit  # 自動生成されたマージメッセージをそのまま使う
```

## 重要

- 編集するのは競合マーカー（`<<<<<<<`〜`>>>>>>>`）の部分のみ
- 競合していない部分は自動でマージ済み、触らない
- 解消が困難・判断に自信が持てない場合は `git merge --abort` で安全に中断し、ユーザーに確認する
