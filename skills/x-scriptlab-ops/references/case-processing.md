# 事例加工支援フロー（B→C→D）

前提: 入力は人が固有名詞を除去した「ぼかし済み(B)」テキストのみ。生データ(A)・ファイルは受け取らない。シート上のカテゴリ値は「症例」（内部管理語彙。公開文には医療語彙を出さない）。

## 1. 受領ゲート

**判定基準の原本はSKILL.md「入口ゲート」**（検知パターン・非引用差し戻し・セッション全停止のルール一式）。本モードでは特に厳しめに適用する:
- ゲート通過まで、B本文の処理（要約・言い換え・部分引用を含む）を一切しない
- 疑わしい（確信が持てない）場合も通過させず差し戻す
- 差し戻し時は種別と行位置のみ伝え、原文は引用しない。ぼかしの方向性（数値は幅に・時期は季節に・業種は一段抽象化）を添える

## 2. C変換（読者視点への翻訳）

- 「こう直した・こう改善した」という**すごさの羅列**を、読者視点の「**あなたの現場にもこの危うさがないか**」に反転する
- 厳しい内容を責めない言い方で。原因は人でなく構造に帰属させる（トーン詳細: tone-guide.md）
- **架空の脚色は一切足さない**。Bにない事実・数値・台詞を創作しない。省略は可、追加は不可
- 型に従う: 具体例→責めずに原因整理→明日からできる小さな一歩。語り出しは直近投稿と散らす

## 3. D公開稿化（最終チェックリスト提示）

公開稿とともに以下を提示し、人の判断を仰ぐ:
- [ ] 社名・人名・地名・特定数値がゼロ
- [ ] **本人テスト**: 当該案件の関係者が読んで「自分の会社だ」と分かる要素がないか
- [ ] 業種×地域×規模×時期×数値の組み合わせで絞り込めないか
- [ ] 避ける表現7項目に抵触しないか（語彙走査＋構造質問の2層）
- [ ] 140字前後・1行目フック等のX投稿定説に沿っているか

## 4. 冷却期間・履歴の機械チェックとクロージング

- ネタ帳の**出所コード(H)・解禁日(I)**で機械チェックする:
  - 解禁日が未来（最低2週間、初期運用中は実務完了後1か月）→公開稿を渡さず保留を提案
  - 同一案件コードが使用済ネタ・投稿済台帳に既出→**生涯1案件1回の超過**として赤旗、処理停止
  - コード・解禁日が未記入→人に確認して記入してもらうまで進めない（フェイルクローズ）
- 台帳の✓症例加工済(I列)の**判断は必ず人**。チャット承認の場合は「OKの返信は3チェック確認を含む」旨を提示文に明記した上でAIが書記記帳する。公開の最終判断も人
- 投稿日時は事例枠（日曜13-15時）を提案して終了

**原則: AIは赤旗を上げるが合否は決めない。ゲートは厳しめ、差し戻しは具体的に、引用はしない。**
