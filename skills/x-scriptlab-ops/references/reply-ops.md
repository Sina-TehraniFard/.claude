# リプライ運用 — 露出づくりの主戦場

目的: フォロワーが少ない立ち上げ期に、投稿の露出と「書き手の実績」を作る。バズ狙いではなく、(1)読者層との接点 (2)配信AI上の実績シグナル (3)投稿の審査入場券（反応→審査→お墨付き→一等地の順序がある）の3つを同時に積む活動。
根拠はすべて `x-scriptlab/knowledge/x-algorithm/`（特にt5・t6・t7）。アルゴリズム側の数値は非公開のため、数値の期待値は語らない。

## 大原則

- **リプライは必ず人（本人）が手で書く。AIによる下書き・定型文・コピペは禁止**。返信の採点では「貼り付けか」「どのアプリから書いたか」等の来歴が収集されており、返信だけがこの情報を使う設計（t5）。AIはこの章では相手候補の下調べ・文面の事後チェックのみ担当できる
- **迷ったら書かない**。返信は0〜3点で採点され、0点は即スパムラベル（相手が大きい場合）。1回の失点が以後の配信全体に響く非対称リスク（t6）
- KPIにはしない。数えるのは週次の件数だけ（後述）。バズ・いいね数を目標にしない

## 相手選び6か条（すべて満たす相手にだけ書く）

1. **大きめのアカウント**: 採点土俵に乗る条件は「相手（または会話の起点の人）のフォロワー規模」。自分の規模は不問。閾値は非公開なので、目安として数千フォロワー以上の相手を選ぶ
2. **健全で落ち着いた投稿**: 炎上中・過激・きわどい投稿への返信は、相手の投稿が問題あり判定になった時点で自分の返信ごと連鎖非表示（t3/t6）。内容に自信があっても避ける
3. **会話の起点（元の投稿）に直接返信**: 返信への返信は露出条件が厳しく、3階層目以降はフォロワーTLに出ない
4. **1スレッド1件のみ**: 同じ画面に自分の発言は原則1件しか出ない。連投は共倒れ
5. **読者層か、読者層が読んでいる相手**: 地方の経営者・税理士・診断士・商工会系・実務系の発信者。トーンは投稿本文と同じ（責めない・具体・平易）
6. **相手の話に具体で応える**: 相槌だけ・一般論・宣伝・自分の投稿への誘導は禁止。数字か経験を1つ添える型（投稿本文の「具体で書く」原則と同じ）

## 守秘・点検

- リプライ文にも**守秘系の機械走査のみ**実施（SKILL.md入口ゲート基準: 社名・人名・特定可能な組み合わせ）。トーン点検はかけない（本人の声が正）
- 現案件由来の話題には触れない（絶対原則3と同じ）

## 効果確認と記録

- **自分のリプライは自分のTLには表示されない**（構造上）。効果確認は相手の投稿の返信欄を直接開いて順位を見る（t6）
- 週次（週末バッチのついで）に記録するのは**件数と気づきだけ**: 「今週◯件・手応えのあった相手の傾向」を1行、x-scriptlab/log/ または計測タブのメモ欄に。返信ごとの成果追跡はしない
- プロフィールアクセスの増減（Xアナリティクス・手動）が実質の成果指標。計測タブH列に転記

## 投稿当日の初動づくり

朝の投稿日はリプライ活動日でもある。投稿の反応は「実績・審査・採点」の三重に効くため、**投稿した日の午前〜昼に2〜3件のリプライ活動を行い、アカウントの動きがある状態を作る**（投稿への直接効果は保証されないが、アカウントの実績形成として合理的・t5/t7）。1日15分まで。義務にしない（続かない設計は失敗）。
