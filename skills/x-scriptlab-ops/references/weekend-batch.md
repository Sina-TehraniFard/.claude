# 週末バッチ手順書

原則: フェイルクローズ。書き込みは必ずID検索で行特定→対象セルのみA1指定更新。日時は`yyyy-MM-dd HH:mm`。人への質問は承認時の1メッセージに集約する（逐次質問しない）。

## 0. 縮退分岐（最初に必ず確認）

人が「今週は無理」「時間がない」「疲れた」「1本だけ」等を言ったら、即このモード。**AIから追加執筆・量産を提案しない。**
1. 投稿台帳の積み済・承認済を読み、キューが何曜日まで持つか計算
2. 「今週は積み増しなし。既存キュー〇本で△曜まで回ります」と1〜2行で報告して終了（所要約1分）
3. 「1本だけ」と言われた場合のみ、一言カテゴリ1本を変換して承認依頼

これは失敗ではなく正規の成功パス。KPIは継続率であり本数ではない。

## 1. 読み取りと目標本数

- `spreadsheets.values.batchGet`で`ネタ帳!A:I`と`投稿台帳!A:P`を一括取得。**ヘッダーが規約と不一致（H/I/P列の欠落含む）なら何も書かず停止・報告**
- ストック数（承認済＋積み済で未投稿）で決定: 5本以上→軽く（0〜2本）／2〜4本→通常（5〜7本）／2本未満→フル7本

## 2. ネタ選定

- 対象: 状態=在庫 **かつ 出所(H)記載あり**。出所未記載は処理対象外とし、一覧で人に報告（フェイルクローズ）
- 出所が案件コードのネタ: 解禁日(I)が未来→選ばず赤旗報告。同一コードが使用済ネタ・投稿済台帳に既出→生涯1案件1回の超過として赤旗報告
- 起票日の古い順に目標数。直近の台帳を見てカテゴリ・形・語り出しの偏りを回避
- 不足時はある分だけで続行し、承認メッセージ内で採掘対話を提案（不足数とカテゴリの穴を提示）。ゼロなら手順0へ

## 3. 変換と下書き書き込み

- 執筆前に references/tone-guide.md と references/examples.md を読む
- 1ネタ最大2案。型・形・140字目安・語り出し5パターンの分散に従う
- 投稿IDは台帳の最大P番号+1から連番。`values.append`でステータス=**下書き**追記（G/H/I✓とP列は空のまま）

## 4. 点検前さばき

- 各案に点検10問（手順はtone-guide.md）。赤旗は**台帳P列に「赤旗:種別:理由」を記入**（守秘系は該当箇所を引用しない）
- AIはボツにしない・合否を決めない

## 5. 承認（1回・1メッセージに集約）

- 全稿を投稿ID付き一覧で**一括提示**。点検結果・赤旗・不足や鮮度などの質問は選択肢形式でこのメッセージにまとめる（例: 「ネタ不足2本 → a.採掘する / b.今週はこのまま」）
- 提示文に明記: 「**OKの返信は3チェック（現案件でない／固有名詞なし／事例加工済）の確認を含みます**」
- 人の返信（例: 「P-0012,0013 OK / P-0014 ボツ / P-0015 赤旗解除:理由〇〇」）を受け、AIが**書記として**G/H/I=✓・F=承認済/ボツを記帳し、記帳内容を復唱報告する（判断は人、記帳はAI）
- **赤旗(P列)のクリアは、人が理由を明示した行のみ。** 理由はO備考に転記。明示のない行はOKと言われてもPを残し、積まない
- **承認タブ経由（非同期）**: 手順5の冒頭で必ず`承認!A2:I1000`を読み、判定済み行（F✓またはG✓）があればSKILL.mdの転記規約に従い先に反映する。**D列「あなたの言葉」が非空の行は、台帳E本文をDの内容で上書きしてから積む**（本人リライト優先。守秘系の機械走査のみ実施、トーン点検はかけない）。チャット承認の代わりに「承認タブのD列に自分の言葉で書き直し、F列に✓を入れておいてください。次回依頼時に反映して積みます」と案内していったん終了してもよい
- 人がシートで触るのは承認タブのみ（他タブへの記入を人に依頼しない。必要な記帳は全てAIが行う）

## 6. プリフライトとBuffer積み

- `mcp__buffer__list_posts`で予約中件数を確認→残枠=10−予約数。**入り切らない分は承認済のまま来週回しを提案**（エラーにしない）
- 処理対象: **承認済 かつ buffer_id空 かつ G/H/I全✓ かつ P(赤旗)空**（冪等・2キー）
- **1本ずつペア処理**: `mcp__buffer__create_post`（addToQueue）→ 成功直後に台帳記帳（F=積み済／L=buffer_id／J=予定日時）→ ネタ帳更新（F使用回数+1、D=使用済）→ 次の1本へ

## 7. 失敗時の動作

- create_post成功→記帳失敗: **即停止**。取得済みbuffer_idを報告に明記し、人に手動記帳を依頼（二重積み防止）
- create_post自体の失敗: buffer_id空のままなので報告して次行へ（次回再実行で回収可）
- 人向けリカバリ: **同じ依頼をもう一度言えば続きから。積み済み（buffer_idあり）は自動でスキップされる**

## 8. 通し読み点検（列の点検）

- 投稿済＋積み済を時系列に並べ、**初見の経営者になったつもりで直近3本を通読**する
- 確認: 語り出し・締め方・カテゴリ・形が3連続で似ていないか。「AIが書いた同じリズム」に見えないか
- 似ていたら順序入れ替え or 1本来週回しを提案（edit/deleteの実行は人の明示確認後のみ）

## 8.5 計測スナップショット

- 台帳の「投稿済」ポスト（K投稿日時あり）について、`mcp__buffer__list_posts`（includeMetrics: true, status: sent）で最新指標を取得し、**計測タブに1行ずつ追記**する（投稿ID・取得日・インプレッション・いいね・リポスト・返信・エンゲージ率。H列プロフィールアクセスは人の手動記入欄なので空のまま）
- 追記専用。過去の行は書き換えない（同一投稿の週次履歴を残す）
- 取得失敗やメトリクス未反映（24時間遅れ）はスキップして次へ。エラーにしない
- 報告では数字の列挙よりも所見を優先: 「エンゲージ率が高かった書き方」「プロフィールアクセスを見る価値がある投稿」を1〜2行で

## 9. 完了報告

- 積んだ本数／Buffer予約残枠／ネタ帳在庫残／赤旗・スキップ・出所未記載の明細／通し読み所見／次週の推奨（採掘要否）を簡潔に
